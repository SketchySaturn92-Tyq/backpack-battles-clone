# 底层逻辑 v0.7

这份文档解释代码怎么跑。v0.1 的分层没变，变的是「形状」「位置」「职业」「事件流」四块。

## 1. 分层（不变）

```
data/      纯数据：道具表、形状运算、职业、联动、常量
core/      纯逻辑：网格、商店、战斗、对手池、单局流程
ui/        渲染：DOM 输出、战斗舞台动画
main.js    装配：把 core 的状态接到 ui，处理事件
```

铁律：
- `data` 不 import 任何东西
- `core` 不 import `ui`，不碰 `document`
- `ui` 不改 `core` 的状态，只读取和回调

所以核心逻辑能在 node 里裸跑：`node tools/test-core.mjs` 就是证明。

## 2. 形状系统（新增）

`data/shapes.js` 提供全部形状运算：

| 函数 | 作用 |
| --- | --- |
| `cells(shape)` | 展开成相对坐标列表 |
| `area(shape)` | 占格数 |
| `size(shape)` | 外接尺寸 |
| `rotateCW/rotateCCW` | 旋转 |
| `normalize` | 裁到最小外接框，去掉四周空行空列 |
| `orientations` | 全部不同朝向（去重，对称形状只返回 1~2 种） |

形状是字符串网格：`'X'` 占格、`'.'` 空。

关键约束（有测试断言保护）：
- 每件道具占格数 ≤ 8，否则塞不进 5 列的小背包
- 至少 10 件是「占格数 < 外接矩形面积」的不规则形状
- 单格道具（面包、宝石）故意保留，用来填凹角

## 3. 网格与整理

`Board` 内部两个结构：

- `cells`：长度 cols×rows 的扁平数组，存 `item.uid`
- `items`：`Map<uid, {item, x, y, shape}>`

所有放置判定都走 `canPlace(shape, x, y, ignoreUid)`：
- 逐个检查形状的每个占用格
- 越界 → 拒绝
- 已被别人占 → 拒绝（`ignoreUid` 是移动自己时忽略自身）

`place()` 先 `remove` 再写 cells，保证「拿起再放下」不会自己挡自己。

整理相关的三个方法：

| 方法 | 用途 |
| --- | --- |
| `allPlacements(shape)` | 列出背包里所有能放下的锚点，UI 可以用来提示 |
| `rotateAt(uid, dir)` | 就地旋转；原地放不下就螺旋就近搜索落点 |
| `findFreeSpot(shape)` | 找第一个能放的位置（买入时用） |

**触发顺序**是第一优先级的设计：

```js
triggerOrder() {
  return this.list().slice().sort((a, b) => (a.y - b.y) || (a.x - b.x));
}
```

按道具**左上角**所在行优先、同行按列排序，结果缓存到 `_order`，
任何增删改都置空缓存。`orderIndex(uid)` 就是它在顺序里的位置。

## 4. 战斗：从属性到事件

`buildUnit(board, opts)` 做五件事：

1. 遍历背包，累加基础属性到 unit
2. 对每件道具算一次 aura：查正交邻居，把邻居的 `aura` 字段加到自己身上
3. 算同类相邻数量（同类武器最多 3 层，每层 −8% 冷却）
4. 整包联动：`synergyBonus(board)` 给出数量奖励
5. 结算联动倍率（伤害/生命/护甲/暴击／治疗都在这一步统一放大）

武器单位里记住 `order` 和起手延迟：

```js
const startDelay = idx * COMBAT.orderStep;   // 每往后一位 +0.12 秒
w.timer = startDelay + cd * (1 - readyFactor);
```

这就是「位置有后果」落地的地方 —— 摆得越靠后，第一次出手越晚。

`simulate(A, B, {seed})` 是固定步长循环（0.05 秒）：

- 每 tick 递减武器 timer，到 0 就打一次
- 命中计算顺序：武器伤害 + 单位伤害 → 法术/远程加成 → 狂战士残血加成
  → 暴击判定 → 破甲 → 护甲减伤（上限 75%，战士被动提到 85%）
- 反伤、吸血、点燃、中毒叠层、冰霜减速、破甲各走独立分支
- 中毒每秒结算一次，失血 = 层数 / 3
- 时长上限 30 秒，外加 40000 tick 双保险

**产出是事件流**，不是文本：

```js
{ seq, t, type, side, foeSide, weaponName, fx, damage, crit,
  targetHpAfter, targetMaxHp, sourceHpAfter, sourceMaxHp }
```

`ui/stage.js` 照着事件播动画：出手方前冲、投射物飞行、命中方闪烁后退、
按 `fx` 叠特效与飘字。逻辑与表现彻底分开 —— 想换表现层不用动战斗代码。

`eventText(ev)` 把事件转成人话，给日志面板和结算用。

确定性来自 `mulberry32(seed)`：同一份构筑 + 同一种子 → 同一结果。
测试里直接断言 `again.winner === sim.winner && again.hpA === sim.hpA`。

## 5. 职业与分支

`data/classes.js` 是纯数据。每个职业给：

```js
{ id, name, bag: {cols, rows}, hp, gold, startItems,
  passive: { name, desc, effect }, branches: [...] }
```

被动通过 `effect` 注入 `buildUnit`：

| effect key | 效果 |
| --- | --- |
| `speed` | 全局攻速加成 |
| `armorCap` | 护甲减伤上限 |
| `freeRefresh` / `sellRatio` | 刷新免费 / 卖出返还比例 |
| `regen` | 每秒回复 |
| `magicDamage` | 法术伤害倍率 |
| `firstWeaponReady` | 第一件武器进场时的冷却折扣 |

分支通过 `bonus` 注入，覆盖更专项的效果（`rageDamage`、`thorns`、
`hpPerFuse`、`maxShopLevel`、`extraGold` 等）。

**为什么这么设计**：职业决定背包形状压力（法师 5 列最难塞），
分支决定数值方向。两者正交，组合出 12 种开局。

## 6. 组合联动

`data/synergies.js` 三部分：

1. `ITEM_TAGS`：给每件道具打标签（fire / frost / poison / heal / shield / blade / ranged / gem / crit）
2. `SYNERGIES`：15 条联动定义，每条给触发条件（tag / cat / any）、需要件数、数值效果
3. `evaluateSynergies(board)` / `synergyBonus(board)` / `progressList(board)`

统计口径**按件数，不按占格数**。这是刻意的：

- 1 格的小件（宝石、毒瓶、面包）容易凑齐联动
- 6~8 格的大件属性强但难凑联动

于是「小件 vs 大件」有了真实取舍，而不是单纯越大越好。

两类规则分工清楚：
- **相邻**（宝石 aura）→ 精准加成，只作用于邻居
- **联动**（数量）→ 整包盘点，不要求相邻

同一 id 的联动只保留最高 tier，避免 3 件和 5 件同时叠加两次。

## 7. 合成

`resolveFusions()` 是收敛循环：

反复扫描场上所有道具，只要有两件正交相邻、且 id 组合命中 `RECIPE_MAP`，
就移除两件、放入产物，重新扫描，直到一轮扫不出新合成。

用循环而非单次扫描的原因：一次合成可能让新产物挨上第三件同名道具，形成连锁。

**放不下时**的处理：产物放不下就还原两件原件并打日志，不让玩家吃亏。
合成产物形状往往比原料大得多（长剑 1×3 → 巨剑十字 6 格），
所以「合成之后要重新整理」是常态，不是意外。

职业联动：驯兽师分支的 `hpPerFuse` 在每次合成后加最大生命。

## 8. 单局状态机

```
PREPARE --startBattle/buy/move--> PREPARE
PREPARE --runBattle--> RESULT
RESULT  --nextRound--> PREPARE | BRANCH | OVER
BRANCH  --chooseBranch--> PREPARE
```

回合收益：`baseRoundGold(6) + 回合数 + 连胜 2 + 分支额外`。

失败掉血：`max(4, (maxRounds - 当前回合) × 0.6 + 3)`，越早输掉血越多。

## 9. 对手池

`makeOpponent(round)` 用 round 派生的种子生成，可复现。

和玩家遵守同样的规则：在**真实的 Board 上**用 `findFreeSpot` 摆道具，
不是凭空给属性。强度由三条曲线叠出：
- 预算 `5 + round × 3`
- 商店等级 `1 + round/4`（上限 5）
- 血量 `55 + round × 2`

前 4 回合对手用 5×7 小背包，第 5 回合起换成 6×8，模拟成长感。
第 6 回合起有 50% 概率完成一次合成。

## 10. 测试

`tools/test-core.mjs` 分 11 组、130 项：

1. 形状系统（不规则性、旋转、朝向去重）
2. 摆放与整理（L 形凹角能塞、旋转失败要就近落位、移动后旧格释放）
3. 触发顺序（上优先、同行左优先、换位置结果不同）
4. 数据表（id 唯一、形状合法、每阶位有货、武器都有 fx）
5. 职业与分支（6 职业 × 2 分支、被动生效、分支加成生效）
6. 商店（买/锁/还回、等级权重、商人免费刷新）
7. 合成（相邻才合成、连锁、不相邻不合成、驯兽师加血）
8. 战斗与事件流（事件字段完整、可复现、宝石相邻才生效）
9. 对手池（每回合有货、后期强于前期）
10. 完整单局（6 个职业各跑一局到结束、空背包/无武器不能开战）
11. 平衡抽样（60 局平均胜场与淘汰率）

`tools/browser-check.mjs` 32 项浏览器验收：职业选择、形状渲染、
拖拽、旋转、顺序面板、战斗舞台、动效元素、结算、分支选择、无 JS 报错。

## 11. 平衡口径

自检里的 60 局抽样跑的是「无脑买」AI：每次把商店 5 格全买、回来就开打。
它是平衡的地板线。当前结果：

- 平均 9.90 胜 / 10.8 回合
- 60 局里 1 局被淘汰

含义：不思考的玩家也大概率能赢到接近满胜，说明当前强度偏软。
这是 v0.2 的刻意选择 —— 先让玩家把「整理」和「职业」这两套新机制吃透，
下一版会收紧对手池预算，把地板线压到 6~7 胜。

## v0.7 新增：背包布与储物箱怎么实现

### 舞台与布

- `data/cloths.js`：`STAGE = {cols:9, rows:7}`、`CELL = 64`，以及 8 块布的定义。
  每块布只存「原始形状 + 价格 + 变换状态」，实际形状由 `resolvedShape(base, {flipped, rotation})`
  现算，顺序固定为先翻转再旋转
- `core/grid.js`：`Board` 多了 `cloth = {id, shape, x, y, flipped, rotation}`。
  `canPlace()` 在原越界与占位检查之外，再加一条「每一格都必须在布上」；
  布本身可 `moveCloth / flipCloth / rotateCloth`，变换前会先把布上的道具摘下来，
  变换后按原相对位置尝试放回，放不下的通过 `returnItemsToCloth()` 返回给上层
- `core/run.js`：`Run` 构造时铺开局布；对外暴露 `buyCloth / moveCloth / flipCloth / rotateCloth`，
  被挤出的道具在这里折成金币并写日志，保证道具不会丢
- `ui/render.js`：`renderBoard` 给每格加 `on-cloth` 与四边描边 class，
  舞台本身透明，可见的只有布；`renderClothBar` 显示当前布与位置，
  `renderClothShop` 画布的俯视图

### 为什么格子不再自适应

原来 `fitBoard()` 按可用高度算格子边长，窗口一变格子就缩，道具跟着漂。
现在 `setCellSize()` 是空实现，`CELL` 固定 64，`fitBoard()` 不再改变布局。
舞台尺寸 = 列数×64 + 间隙，固定不变。

### 商店拖进背包

- `renderShop` 的卡片上挂 `pointerdown`，拖出一枚跟随光标的幽灵图标
- 松手时把屏幕坐标换成格子坐标，交给 `run.buyAt(index, x, y)`：
  先校验 `canPlace`，通过才扣钱落位，所以不会出现「买了却放不下」
- 拖拽结束后 350ms 内的 click 会被忽略，避免浏览器补发事件导致买两次

### 储物箱

- `Run.storage` 是不限容量的数组，`storeItem(uid)` 从棋盘移除并推入，
  `takeItem(uid)` 用 `findFreeSpot` 找回背包空位
- 存在箱子里的道具不参与合成、光环和战斗结算

### 自检口径

- `tools/test-core.mjs`：背包布 15 项（含布外不可放、换布不丢道具、挪布道具跟随、
  翻转旋转后仍在布上、重复买与钱不够被拒）
- `tools/browser-check.mjs`：格子固定 64px、储物箱位置、立绘尺寸、角色符号数量、
  开始按钮居中

## v0.7.1 新增：战斗页怎么画双方背包

- `Run.runBattle()` 的结果里补了 `myCols / myRows / foeCols / foeRows / myCloth`，
  因为渲染要还原棋盘尺寸和布的变换状态
- `renderMiniBoard({cols, rows, cloth, items})` 输出一块纯定位的缩略图：
  每格一个 `.mb-cell`（在布上的加 `on-cloth` 与四边描边），每件道具一个 `.mb-item`
  按 `x/y` 绝对定位。单格 34px，比整理页的 64px 小一半
- `BattleStage.setup()` 收 `boardHtml` 与 `stats`，渲染成三段：
  `.stage-top`（背包对峙）/ `.stage-bottom`（小立绘 + 中间数值卡）/ `#stage-log`
- 对手的背包没有布（AI 的 Board 不铺布），缩略图会退化成「只有道具」
