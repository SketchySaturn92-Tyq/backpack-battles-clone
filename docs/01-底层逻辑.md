# 底层逻辑

这份文档解释代码怎么跑，改代码前先看这里。

## 1. 分层

```
data/      纯数据：道具表、常量、商店权重
core/      纯逻辑：网格、商店、战斗、对手池、流程
ui/        渲染：DOM 输出、样式映射
main.js    装配：把 core 的状态接到 ui，处理事件
```

规则：
- core 不许 import ui，不许碰 document。
- ui 不许改 core 的状态，只读取和回调。
- data 不许 import 任何东西。

这条边界让核心逻辑可以在 node 里裸跑（tools/test-core.mjs 就是证明）。

## 2. 背包是网格 + 归属表

Board 内部有两个东西：
- cells：长度 cols×rows 的扁平数组，每格存 item.uid 或 null。
- items：Map，uid → { item, x, y, shape }。

道具的形状是字符串数组，'X' 占格，'.' 空。shapeCells() 把它转成相对坐标，
加上锚点 (x,y) 就是绝对占用格。所有放置判定都走这一个函数，所以旋转、
拖拽、合成的判定口径永远一致。

关键约束：
- canPlace(shape, x, y, ignoreUid) 同时检查出界、占位冲突；ignoreUid 用于移动自身。
- place() 先 remove 再写 cells，保证「拿起再放下」不会自己挡自己。
- neighbors(uid) 用正交四邻探测，返回去重后的 uid 集合，是相邻增益的唯一来源。

## 3. 战斗是确定性模拟

入口 buildUnit(board) → simulate(A, B, {seed})。

buildUnit 做三件事：
1. 遍历背包所有道具，累加基础属性到 unit。
2. 对每件道具算一次 aura：查它的正交邻居，把邻居身上的 aura 字段加到自己身上。
   aura 只吃相邻一次，不叠加距离，避免宝石堆得越远越强。
3. 武器单独成项，同类相邻（武器挨武器）最多叠 3 层，每层减 10% 冷却。

simulate 是固定步长循环，步长 0.05 秒：
- 每 tick 递减每个武器的 timer，到 0 就打一次，然后 timer += cooldown。
- 命中：dmg = 武器伤害 + 单位伤害，暴击判定用种子随机，再按护甲百分比减伤，
  护甲减伤上限 75%。
- 反伤：被打时如果对方有 thorns，反噬攻击方。
- 回复：heal 按 healCooldown 触发，regen 按秒累计取整。
- 上限：COMBAT.timeLimit 秒或 20000 tick，双保险防死循环。

确定性来自 mulberry32(seed)。同一份构筑 + 同一种子 → 同一结果，
所以测试可以断言「again.winner === sim.winner」。

## 4. 合成

resolveFusions() 是一个收敛循环：
反复扫描场上所有道具，只要有两件正交相邻、且 id 组合命中 RECIPE_MAP，
就移除这两件、放入产物，然后重新扫描，直到一轮扫不出新合成。

为什么用循环而不是单次扫描：一次合成可能让新产物挨上第三件同名道具，
形成连锁。用 while + fusedAny 标志保证连锁能跑完。

放不下时的处理：产物放不下就把两件原件还原回背包，并打日志说明，
不让玩家吃亏。

## 5. 单局流程状态机

```
PREPARE --startBattle/buy/move--> PREPARE
PREPARE --runBattle--> RESULT
RESULT  --nextRound--> PREPARE 或 OVER
```

Run 类持有 header（血量/金币/回合/胜场）、board、shop、log、history。
所有变更都集中在 Run 的方法里，UI 只调用方法然后重绘。

回合收益：baseRoundGold(6) + 回合数 + 连胜奖励 2。回合越往后钱越多，
用于对抗日渐变强的对手池。

失败惩罚：掉血 = max(4, (maxRounds - 当前回合) × 0.6 + 3)。
越早输掉血越多，逼玩家前期也要认真配。

## 6. 对手池

makeOpponent(round) 用 round 派生的种子生成，保证同一回合的对手可复现。

强度曲线由三个东西叠出来：
- 预算：4 + round × 3 金币的购物能力。
- 商店等级：1 + round/5，最高 4，决定能抽到几阶道具。
- 血量：55 + round × 2。

每次还随机挑一个流派（双刃 / 铁壁 / 毒系 / 宝石 / 饱食），流派决定它偏好买哪类道具。
这样每一局的对手组合不同，但强度是可预期的。

## 7. 平衡口径

自检里的 60 局抽样跑的是「无脑买」AI：每次把商店 5 格全买、回来就开打。
它是平衡的地板线。当前结果：

- 平均 9.83 胜 / 11.1 回合
- 60 局里 1 局被淘汰

含义：不思考的玩家也大概率能赢到接近满胜，说明当前强度偏软。
这是 v0.1 的刻意选择——先让玩家熟悉摆放和合成，后续版本会调高
对手池预算和血量，把地板线压到 6~7 胜。

## 8. 美术资源接入

图标路径约定 assets/icons/{item.id}.png，缺失时 img 的 onerror 会把图隐藏，
不影响玩法。资源由 Meowa 生成，见 tools/gen_art*.sh。

## 9. 测试

tools/test-core.mjs 覆盖七组：
数据表完整性、网格放置与旋转、商店买卖与权重、战斗判定与确定性、
对手池强度曲线、完整单局跑通、平衡抽样。

跑法：npm test，或直接 node tools/test-core.mjs。
