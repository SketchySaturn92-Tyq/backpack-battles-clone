# 部署与发布

游戏是纯静态页面。本机有公网 IP，所以静态服务直接监听 0.0.0.0，端口对公网开放，
不走隧道、不需要任何中转。

## 在线地址

- 地址：http://218.13.157.146:19991
- 端口：19991（公网直接可达）
- 本机服务单元：catsco-backpack-battles.service
- 服务目录：/srv/catsco-agent/apps/backpack-battles-clone

注意是 http 不是 https：直接暴露端口没法上证书，浏览器地址栏会出现"不安全"提示。
这只是缺少 TLS，不影响游玩。

## 运行方式

```
sudo systemctl status  catsco-backpack-battles.service
sudo systemctl restart catsco-backpack-battles.service
```

- 单元文件：/etc/systemd/system/catsco-backpack-battles.service
- 启动命令：`/usr/local/bin/node tools/serve.mjs /srv/catsco-agent/apps/backpack-battles-clone 19991`
- Restart=always、RestartSec=3，已 enable（开机自启）
- 监听 0.0.0.0:19991

本套服务与快传（19996）、项目推进看板（19995）同机同网段，端口各自独立。

## 改代码后怎么生效

只改前端（html / css / js / 图标）**不用重启**：静态服务每次请求都读盘，刷新页面即可。
响应头带 `Cache-Control: no-cache`，浏览器不会拿旧缓存。

只有改了 serve.mjs 本身，或换了端口、目录，才需要：

```
sudo systemctl restart catsco-backpack-battles.service
```

改完建议清掉作品目录里的临时文件再推送，仓库里只留源码与资源。

## 为什么不用隧道方案

最早发布走的是 Artifact 隧道（固定 https 域名）。已下架，改用公网 IP 直连，原因：

- 直连就是本机端口，路径没有 `/<应用id>/` 前缀，相对路径引用一律正常
- 不依赖外部网关，少一个故障点
- 代价是没有 TLS，且公网 IP 变化时需要重新告知访问者

如果之后要换回域名方案，注意两点：页面资源必须用相对路径；需要在应用里自己用
`viewer.id` 做权限，因为隧道地址本身是公开的。

## 验收清单

每次改完或重启后按这套走：

1. 公网地址返回 200：

```
curl -s -o /dev/null -w '%{http_code}\n' -m 15 http://218.13.157.146:19991/
```

2. 页面标题正确、静态资源不 404（静态页 404 会白屏）：

```
for f in src/css/style.css src/js/main.js src/js/core/run.js assets/icons/sword.png; do
  printf '%s → %s\n' "$f" "$(curl -s -o /dev/null -w '%{http_code}' -m 15 "http://218.13.157.146:19991/$f")"
done
```

3. 服务 enabled + active：

```
systemctl is-enabled catsco-backpack-battles.service
systemctl is-active  catsco-backpack-battles.service
```

4. 浏览器在公网地址上真跑一遍（会打完整单局并抓 JS 报错）：

```
cd ~/apps/backpack-battles-clone
REMOTE_URL="http://218.13.157.146:19991/" node tools/browser-check.mjs
```
