# 部署与发布

游戏是纯静态页面，发布走 Artifact 隧道：本机起一个静态服务器，网关把公网请求转进来。
不需要公网 IP，不需要开入站端口。

## 在线地址

- 主地址：https://artifact.catsco.cc/backpack-battles/
- 备用域名：https://artifact.catsco.cn/backpack-battles/
- 应用 id：backpack-battles
- 本地端口：19999（只监听 127.0.0.1）
- 远端端口：28248（网关分配，不可改）

两个域名指向同一份内容，哪个能打开用哪个。

## 为什么静态页面也要起进程

网关往「端口」转发，不是往目录转发。所以页面即使是纯文件，也必须有个东西在监听。
用的是 Artifact 技能自带的静态服务器：

```
node /srv/catsco-agent/skills/artifact-publish/connector/serve-static.mjs <目录> <端口>
```

它把 `/<应用id>/` 前缀去掉后按剩余路径找文件，所以页面里的资源引用必须写相对路径
（`src/js/main.js` 可以，`/src/js/main.js` 会打到网关根而 404）。改前端时留意这条。

## 两个常驻服务

| unit | 作用 | 重启策略 |
| --- | --- | --- |
| catsco-artifact-backpack-battles.service | 连接器（隧道） | on-failure，下架退出码 78 不重拉 |
| catsco-artifact-backpack-battles-app.service | 应用本体（静态服务） | always |

两个都必须 enabled + active。少任何一个，公网都是 502 —— 连接器没起和本体没跑的症状一样。

检查：

```
systemctl is-enabled catsco-artifact-backpack-battles.service catsco-artifact-backpack-battles-app.service
systemctl is-active  catsco-artifact-backpack-battles.service catsco-artifact-backpack-battles-app.service
```

诊断 502 时先看归属：

- 连接器状态不是 connected → 重启连接器服务
- 连接器 connected 但本地端口没人听 → 重启应用本体服务

连接器状态文件：/srv/catsco-agent/data/backpack-battles/connector-state/status.json
（该文件归 root，读它要 sudo）

## 状态目录

```
/srv/catsco-agent/data/backpack-battles/connector-state/
├─ connector.json   连接器配置（含远端端口、密钥路径）
├─ id_ed25519       本应用专用密钥
├─ id_ed25519.pub   已作为 Deploy Key 思路注册到网关
├─ known_hosts      钉住隧道对端
└─ status.json      运行状态（root 所有）
```

密钥是本应用专用的，不要和别的应用复用。

## 重新发布与更新内容

改完代码不用重新发布，页面立刻生效（静态服务直接读目录）。只有换端口、改名、
调上传上限才需要再 publish 一次同一个 id：

```
cd /srv/catsco-agent/skills/artifact-publish/connector
ARTIFACT_STATE_DIR=/srv/catsco-agent/data/backpack-battles/connector-state \
  node artifact-cli.mjs publish backpack-battles "背包乱斗复刻版" 19999
```

注意 `ARTIFACT_STATE_DIR` 必须显式传：发布脚本默认在 `/opt/xiaoba-cloud-bot/state/artifacts/<id>`
找公钥，而本机实际状态目录在 `/srv/catsco-agent/data/` 下，不传会报「找不到公钥」。

改完前端资源后，记得重启应用本体服务让缓存口径统一（静态服务带 `no-cache`，一般不必）：

```
sudo systemctl restart catsco-artifact-backpack-battles-app.service
```

## 下架

```
cd /srv/catsco-agent/skills/artifact-publish/connector
node artifact-cli.mjs delete backpack-battles                     # 移除网关路由，公网立刻 404
sudo systemctl disable --now catsco-artifact-backpack-battles.service \
                              catsco-artifact-backpack-battles-app.service   # 立刻停服
```

下架只删路由，本机文件和数据都在。用同一把公钥可以重新发布。

## 验收清单

每次发布或大改后按这套走：

1. 两个域名都返回 200
2. 页面标题与首个区块内容正确
3. 页面引用的 js / css / 图标都能取到（静态页面 404 会白屏）
4. 身份端点如实返回游客态，不报错
5. 两个服务都 enabled 且 active
6. 浏览器在公网地址上真跑一遍：

```
cd ~/apps/backpack-battles-clone
REMOTE_URL="https://artifact.catsco.cc/backpack-battles/" node tools/browser-check.mjs
```

第 6 步会跑完整单局并抓 JS 报错，截图落在 art/verify/。
